# 可信完成与低干扰监控切片方案

> 状态：已完成（2026-08-10 完成 S-TRUST-1、S-TRUST-2、S-TRUST-3、S-PROBE-1、S-CONTROL-1、S-ACC-1）。
> 权威边界：[`CONTEXT.md`](../CONTEXT.md)、[ADR-0009](adr/0009-content-blind-controller.md)、[ADR-0010](adr/0010-trusted-worker-completion.md)。

## 目标与边界

**做**:

- 把 Production Orchestrator 收敛为顺序 Goal Prompt 调度器。
- Development Task 或 Continuation Task 返回结构化 `COMPLETED` 后直接推进下一 Slice。
- 保留 Project Write Lease、模型策略、暂停/终止、失败闭合和自动压缩三任务接力。
- 正常监控只消费结构化状态；Host 缺少压缩事件时才启用分段 Compaction Content Probe。
- 继续解析旧 Production Plan 字段和旧 Run 状态，但不让它们参与新 Run 判断。

**不做**:

- 不检查 Git diff、提交文件、`owned_paths`、Protected Change 或内容相关性。
- 不执行或复跑 Slice `checks`，不校验 `expected_artifacts`、digest 或 CompletionReceipt。
- 不检查 commit、HEAD、checkpoint 是否产生或刷新。
- 不用 Worker 正文判断进度、质量、完成或失败原因。
- 不改变 Compression Task 读取 Source Thread、生成 Handoff 和 Continuation Task 接力的职责。
- 不 push，不自动替用户恢复 `NEEDS_USER`，不修改 Development Task 的工程纪律。

## 冻结运行契约

### 1. 可信完成状态机

```text
IDLE -> PREPARING -> SLICE_RUNNING

SLICE_RUNNING + TURN(COMPLETED)
  -> PREPARING(next Slice)
  -> DONE(final Slice)

SLICE_RUNNING + TURN(FAILED|INTERRUPTED)
  -> NEEDS_USER

SLICE_RUNNING + COMPACTION_STARTED
  -> COMPACTION_WAIT
  -> SLICE_RUNNING                    # 30 秒内压缩完成
  -> SOURCE_INTERRUPTING              # 30 秒超时
     -> HANDOFF_EXPORTING
     -> CONTINUATION_STARTING
     -> SLICE_RUNNING
```

- 新 Run 不进入 `VERIFYING`、`COMMITTING` 或 `CHECKPOINTING`。
- 三个旧状态保留解码、`status` 与 `abort` 兼容，不允许按新语义恢复推进。
- `COMPLETED` 是 Host 的结构化 Turn 终态，不解析最终回复或模型自述。
- `FAILED`、`INTERRUPTED`、模型改道、协议错误和租约错误仍确定性闭合。

### 2. Goal Prompt 与兼容字段

```text
commit_mode=none
  -> 设定goal：阅读checkpoint，实现<SliceId>，完成后刷新checkpoint

commit_mode=after_slice
  -> 设定goal：阅读checkpoint，实现<SliceId>，完成后commit，刷新checkpoint
```

- `commit_mode` 与 Slice override 只在 `turn/start` 前决定 prompt 文案。
- 当前 Slice 已投递后拒绝 override；未来 Slice 仍可覆盖。
- V1 的 `owned_paths`、`exclusions`、`checks`、`expected_artifacts` 保持语法兼容但运行时惰性。
- 本计划不引入 Production Plan V2；删除旧字段另立迁移方案。

### 3. Controller 零工作产物观察

普通完成路径不得调用或等价替代以下能力：

```text
GitChangeGuard.captureBaseline/classify/assertCommittable
SliceExecutor.start/collect
SliceVerifier.verify
GitGoalCompletionGuard.observe
git diff/show/status/rev-list
checkpoint read/hash/mtime inspection
artifact read/hash
```

自动压缩接力也不得为了 `expected_owned_diff_digest` 检查工作区；Handoff 与 Continuation 只绑定 Run、Slice、Source/Compression/Continuation 身份、持久 Source revision 和 Evidence Index。

### 4. 自动压缩探测

首选路径始终是 Host 的结构化 `contextCompaction` start/completed 事件，事件可用时正文探测调用数必须为零。

仅当 Host 明确报告该事件能力不可用时，启动隔离 `CompactionContentProbe`：

```typescript
type CompactionProbeResult =
  | { kind: 'NO_COMPACTION' }
  | { kind: 'COMPACTION_SEEN'; observedAt: string }
  | { kind: 'PROBE_FAILED'; reasonCode: string }

probe(threadId, turnId, elapsedMs) -> CompactionProbeResult
```

```text
elapsed < 20m       -> 不读取
elapsed = 20m       -> 读取一次
20m < elapsed <30m -> 不读取
30m..40m            -> 30、35、40 分钟读取
elapsed > 40m       -> 42、44、46... 分钟读取
Turn 终止或已发现压缩 -> 立即停止调度
```

- Probe 可读取 Worker Content，但原始正文不得进入 Controller、监督 Codex、RunStore、日志或错误消息。
- Probe 只投影上面的枚举 DTO，不评价任务内容，也不报告“看起来停滞”。
- `COMPACTION_SEEN` 后复用既有 30 秒 Compaction Timeout 与三任务接力。
- `PROBE_FAILED` 进入可解释失败闭合，不提高正文读取频率。

### 5. 监督 Codex 的监控边界

- `auto-slice-control` 的“继续监控”只允许调用 `auto-slice-controller status`。
- 禁止监督任务使用 `list_threads`、`read_thread`、`wait_threads` 或等价能力观察 Development/Source/Continuation Task。
- 禁止为解释状态而读取工作区、Git、日志、checkpoint 或任务命令输出。
- 监督任务只报告 Run/Slice 身份、枚举状态、状态版本和列出的恢复选项。
- Compaction Content Probe 由 Controller 内隔离端口调度，不把正文返回监督任务。

## S-TRUST-3 · 压缩接力去工作区绑定

- **做**：保留 Source interruption、持久 revision、Compression/Handoff/Evidence 与 Continuation 身份绑定；移除压缩接力前后的 owned diff、Protected Change 和 workspace snapshot 要求。

## 端到端验收矩阵

| 场景 | 预期 |
| --- | --- |
| 两刀均 `COMPLETED` | 直接 `DONE`，不出现验收三态 |
| Worker 修改任意额外文件 | 不检查、不阻断、不报告文件名 |
| `after_slice` 无 commit 或多 commit | 不检查，仍按结构化终态推进 |
| checkpoint 未变化或不存在 | 不检查，仍按结构化终态推进 |
| Worker `FAILED` / `INTERRUPTED` | `NEEDS_USER`，不进入下一刀 |
| Host 支持压缩事件 | 只消费结构化事件，正文 probe 零调用 |
| Host 不支持压缩事件 | 严格按 20/30/35/40/42... 探测 |
| 40 分钟前后 Turn 已终止 | 取消后续探测，零迟到读取 |
| 压缩超过 30 秒 | Source -> Compression -> Continuation 三任务接力 |
| revision 或 Evidence 无效 | Handoff 前后对应门禁失败闭合 |
| 旧 V1 Plan | 正常解析，旧验收字段不参与运行 |
| 旧验收态 Run snapshot | 可 status/abort，不按新语义 resume |
| 监督用户说“继续监控” | 只轮询 Run status，不打开 Worker Task |
